ChromaDB
- 기억 관리
	- 이벤트가 발생하거나, 유저의 상호작용이 일어날 때 그 상황과 유사한 기억 상위 10개(중요도 점수를 이용해)를 선정하여 가져와서 	   llm에 입력
	- 중요한 기억 선별하기 : Recency, Importance, Relevance -> 
	   (최근성 점수 x 가중치) + (중요도 점수 x 가중치) + (연관성 점수 x 가중치) 
Database:
    Relational DB (MySQL): 유저/NPC 스탯, 인벤토리, 소문 ID, 호감도 등 수치 및 정형 데이터
    Vector DB (ChromaDB): NPC의 에피소드 기억, 성찰 결과 등 비정형 텍스트 데이터

Backend: Python, FastAPI (API 서버 및 비동기 처리), Pydantic (데이터/JSON 검증), SQLAlchemy (ORM)

Frontend: React + Phaser 3 (게임 엔진 및 렌더링)


조작: WASD(이동), E 또는 마우스 클릭(상호작용 - 타겟팅 우선순위 로직 적용)
시간 시스템: 시간 넘기기 기능 존재, 현실 1초 = 게임 1분
대화 연출: 이모지 말풍선 기본 활용, 트위닝(Tweening) 애니메이션 적용.

시야/은신 (Stealth):
    맵 곳곳에 HIDDEN=TRUE 속성의 수풀 타일 배치.
    유저 진입 시 phaser-raycaster 플러그인을 활용한 NPC 시야각(광선투사) 검사.
    NPC 시야 밖이면 은신 성공 (엿듣기 아이콘 활성화), 걸리면 은신 실패.

최적화: 유저 시야 거리 밖의 NPC는 LLM 호출을 생략하고 수학적 확률 연산으로만 친밀도 업데이트.

추후 추가 가능 인원 : 요리사(2인 이상), 목수/나무꾼(평소엔 나무를 베어 팔고, 화재 이벤트 발생 시 집 수리), 광부, 경찰 1인 추가, 추가 일반 시민

특수 시설: 도박장, 암시장 (밤에만 몰래 운영, 해당 NPC와의 친밀도가 높아야 입장 가능)


인지 및 소문 전파 로직
- 정보 획득: 시야 범위(광선투사) 내 사건 목격 또는 타인과의 대화, 엿듣기.
- 소문(소문마다 고유 ID를 부여하고, NPC의 DB에 "이 ID의 소문은 이미 알고 있음"이라는 태그를 달아 중복 전파를 막음)
	- 시스템 프롬프트로 소문 왜곡 제어(성격에 따라, 어느정도만 왜곡되게)
	- 확률 로직으로 프롬프트를 동적으로 제어(소문 왜곡)
	- 정보의 원본(Fact)과 소문(Rumor) 태그를 통해 분리 저장(NPC에 따라 소문 진압 가능)


NPC 기억 및 프롬프트 구조

LLM 호출 시 주입되는 컨텍스트 구조 (충돌 방지를 위해 MySQL의 팩트를 최우선 연기 지침으로 설정):
1. 고정된 자아: (이름, 직업, 성격)
2. 현재 상태: (MySQL 기준 현재 호감도, 기분, HP 등 - ChromaDB 기억보다 최우선 적용)
3. 최근 대화 내역 (Short-term Context): 방금 전 유저와 나눈 마지막 대사 5~10개 (대화 끊김 방지)
4. 검색된 기억 (ChromaDB): 유저 상호작용/이벤트 발생 시 (최근성x가중치) + (중요도x가중치) + (연관성x가중치) 점수 상위 10개 추출.
5. 성찰 및 요약: 과거의 깨달음이나 감정선 요약.


성찰 및 루틴 재계획 (핵심 루프)
- 트리거: 유저가 침대에서 잠들 때 실행 (하루 1회).
- 기절 시스템 (Pass-out): 유저가 잠을 자지 않고 버틸 경우, 새벽(예: 새벽 2시)에 강제 기절. 암전과 함께 병원/집으로 이동되며 페널티 부과. 이때 강제로 글로벌 성찰/루틴 갱신 로직 실행.
- 프롬프트로 제약을 걸어 할루시네이션 제어
- 성찰 팩트체크: LLM의 할루시네이션을 막기 위해 성찰 결과를 바로 DB에 넣지 않고 MySQL의 관계 데이터와 크로스체크.
- 루틴 생성: 소문과 성찰으로 루틴 제어(루틴을 하드코딩하지 않고, 백엔드에서 llm에게 일일 시간표를 새로 짜라고 지시(JSON))


이벤트 및 World Event Manager

백엔드 매니저는 다음 순서로 세계를 업데이트합니다:
- 환경 이벤트 발생: 정기/돌발 이벤트 시작 여부 체크.
	- 이벤트 풀: 결혼식, 장례식, 화재
	- 이벤트 발생 시, 생성된 개별 루틴을 무시하고 '이벤트 전용 시간표'로 강제 오버라이드(덮어쓰기).
- 기억 브로드캐스팅: 주변 NPC들에게 주요 사건 알림. (단, is_dead = True인 사망 NPC는 브로드캐스트 및 루틴 생성에서 완전 배제).
- 비동기 루틴 갱신 (Async LLM):
	- FastAPI의 비동기 처리(async/await)로 다수 NPC의 루틴을 동시 생성.
	- 이때 클라이언트(Phaser) 화면에는 로딩 바(Progress Bar) 표시.
	- 폴백 루틴(Fallback): LLM 에러나 JSON 파싱 실패 시 게임 프리징을 막기 위해 '기본 생존 시간표(집->일터->집)'를 강제 주입.
- 관계 데이터 업데이트: 모든 수치를 MySQL에 반영 후 다음 날 아침으로 전환.



LLM : GPT-4o-mini, Llama-3-8B-Instruct-abliterated / Hermes-2-Pro-Llama-3
Tiled (Map Editor)
Universal LPC Spritesheet Character Generator
이모티콘(말풍선) 활용, 트위닝(Tweening) 애니메이션
- 대화 : 이모지 말풍선이 기본, 거리 기반으로 유저 시야 밖에서는 LLM을 호출하지 않고 수학적 확률으로 친밀도 업데이트
- 수풀 등의 HIDDEN=TRUE로 만들어주는 타일 곳곳에 생성, 유저가 수풀 타일로 들어가는 순간 주변 NPC의 시야각 안에 유저가 있는지 
  검사 후 안보고있으면 성공, 보고있으면 은신 실패(엿듣기 로직 -> 엿듣기 아이콘 활성화)
